# Contributing to agent-eval-harness

- Make each change on a branch and merge through a pull request into `main`.
- Keep explanations in user-facing documentation. Keep code, tests, fixtures, configuration, and workflows free of comments.
- Develop behavior changes test-first. Confirm the new test fails for the expected reason, then implement the change and run it again.
- Give each PR a concise description with **What changed**, **Why**, and **How it was tested**. Name the commands or manual checks and their outcomes. For behavior changes, include the failing and passing results. State when a relevant check could not run.
- Use `Closes #N` for an issue the PR completes. Link partial work without a closing keyword. See the [issue tracking guide](docs/issue-tracking.md).
